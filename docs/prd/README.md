# Product Requirement Documents (PRDs)

Formal PRDs for features or major milestones. Use when a section README is not enough scope — e.g. a web app feature with multiple user stories, data contracts, and release criteria.

## When to Create a PRD

| Use section docs (`docs/course/`) | Use a PRD (`docs/prd/`) |
|-----------------------------------|-------------------------|
| Course learning notes | Shipping a product feature |
| Concept summaries | Multi-story epics |
| Personal reference | Stakeholder review needed |

## Template

Start from [`templates/requirements.md`](../../templates/requirements.md) and expand with:

- Problem statement
- Target users
- User journeys (diagram or steps)
- Functional requirements
- Non-functional requirements
- Data contracts
- Release criteria
- Open items (Clarification Gate)
